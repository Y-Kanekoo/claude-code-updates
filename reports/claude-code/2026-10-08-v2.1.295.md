## 変更内容

### 新機能
<!-- sources:R1 -->
- **失敗時にアクションをブロックする `onFailure: "block"` オプションの追加**
  - 関連: `onFailure`
  - コマンドや HTTP フックが開始できない、タイムアウトする、または予期しない終了コードになると、アクションがブロックされます。
<!-- sources:R2 -->
- **Program Status Protocol (OSC 7501) のサポート追加**
  - 関連: `OSC 7501`
  - OSC 7501 に対応した端末は、Claude Code が作業中・待機中・完了のいずれかの状態であることを表示できます。
<!-- sources:R3 -->
- **`/copy` ピッカーで引用テキストを除去してコピー**
  - 関連: `/copy`
  - ドラフトメッセージをコピーする際、`>` マーカーが除去されたテキストがクリップボードに入ります。
<!-- sources:R4 -->
- **プラグイン操作時の設定ファイルロード失敗警告の追加**
  - 関連: `claude plugin install` / `enable` / `disable` / `marketplace add`
  - `claude plugin install`、`enable`、`disable`、`marketplace add` 実行時に、書き込み先設定ファイルがロードできない場合に警告が表示されます。
<!-- sources:R5 -->
- **端末での標準エラー出力に待機状態表示を追加**
  - 関連: `stderr`
  - 端末上で `claude -p` が最後のターン後も開いたままの場合、何を待機しているかが stderr に表示されます。
<!-- sources:R6 -->
- **Claude アプリゲートウェイの上流タイムアウト設定 `timeouts.upstream_ttfb_ms` のサポート追加**
  - 関連: `timeouts.upstream_ttfb_ms`
  - Bedrock、Vertex、Foundry などのクラウド上流で、ストリーム開始までの最大待機時間をミリ秒単位で設定できるようになり、超過するとフェイルオーバーまたは 502 エラーになります。
<!-- sources:R7 -->
- **ターン停止時に「Backgrounding cancelled」メッセージが表示**
  - 関連: `Backgrounding cancelled` / `←`
  - `←` が現在のツール完了を待機中にターンを停止すると、キャンセルメッセージが追加されました。
<!-- sources:R8 -->
- **Claude apps ゲートウェイ上流にオプションの models リストを追加**
  - 関連: `models` / `*`
  - 各アプリの上流設定で指定したモデルのみが送信され、フェイルオーバー時も同様に適用されます。
<!-- sources:R9 -->
- **forceLoginMethod と forceLoginGatewayUrl の設定をユーザー設定に追加**
  - 関連: `forceLoginMethod` / `forceLoginGatewayUrl`
  - 管理設定がないマシンで、`forceLoginMethod: "gateway"` と `forceLoginGatewayUrl` を設定すると、/login が指定ゲートウェイで開きます。
<!-- sources:R10 -->
- **プラグイン README にインストール行が無い場合のアドバイスを追加**
  - 関連: `claude plugin validate`
  - `claude plugin validate` がインストール行を検出できないと、貼り付け用の行を表示し、終了コードは変更しません。
<!-- sources:R11 -->
- **上流リクエスト ID を inference 監査イベントに含める**
  - 関連: `upstream_request_id`
  - Claude apps ゲートウェイの `inference` 監査イベントに `upstream_request_id` が追加され、Bedrock や Anthropic API のリクエスト ID が記録されます。
<!-- sources:R12 -->
- **$.ui.notify によるモッド向けネイティブ通知機能を追加**
  - 関連: `$.ui.notify`
  - モッドは `$.ui.notify` を使用して、設定された通知方法でチャンネル名と共に通知を送信できます。
<!-- sources:R13 -->
- **モジュールのボタンに子要素として文字列と Text を追加**
  - 関連: `Button` / `Text`
  - これにより、リストの行全体がチップや詳細テキストを含むプレス可能な要素となります。
<!-- sources:R14 -->
- **`CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS` の追加**
  - 関連: `CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS` / `CLAUDE_CODE_RETRY_WATCHDOG`
  - 未対応のリトライモードが 429 および 529 エラーで待機する最大時間を制限できるようになりました。
<!-- sources:R15 -->
- **`request-id` ヘッダーの追加**
  - 関連: `request-id` / `request_id`
  - Claude アプリゲートウェイの成功応答に request-id ヘッダーが含まれ、テレメトリの request_id が監査ログと一致します。

### 改善
<!-- sources:R101 -->
- **Amazon Bedrock 上の Claude アプリゲートウェイでトークン数取得方法を改善し、`/context` と大容量ファイル読み取りで AWS の CountTokens API を使用するように変更**
  - 関連: `/context` / `bedrock:CountTokens`
  - 以前は1トークンモデルリクエストでトークン数を取得していたが、現在は AWS の CountTokens API を利用し、正確なトークン数が得られるようになり、`bedrock:CountTokens` 権限が必要になる。
<!-- sources:R102 -->
- **Claude アプリゲートウェイが PostgreSQL データベースが読み取り専用の場合、30 秒ごとに警告をログ出力し、失敗内容と復旧方法を示すように改善**
  - 関連: `PostgreSQL`
  - データベースが読み取り専用になると、以前は警告が出なかったが、現在は30秒ごとに警告がログに記録され、失敗原因と復旧手順が示されるようになった。
<!-- sources:R103 -->
- **権限プロンプト待ちセッションの表示をサーバー名と可読名に変更**
  - 関連: `mcp__server__tool`
  - `mcp__server__tool` 識別子ではなく、サーバー名と人間が読める名前で表示されるようになりました。
<!-- sources:R104 -->
- **バックグラウンドリクエストでHaiku 4.5を優先使用**
  - 関連: `Haiku 4.5`
  - Claudeアプリゲートウェイは、バックグラウンドリクエスト時にHaiku 4.5を使用し、利用不可の場合はセッションのモデルへフォールバックします。
<!-- sources:R105 -->
- **Amazon Bedrock地域外のモデルリクエスト処理を改善**
  - 関連: `models:`
  - `models:` にリストされていないモデルでも、ゲートウェイが自地域のモデルを試行し、拒否された場合はモデル名を通知します。
<!-- sources:R106 -->
- **使用制限警告にアカウントの追加使用情報を表示**
  - 関連: `rate_limit_event`
  - ヘッドレス環境での `rate_limit_event` 警告が、アカウントに追加使用が有効かどうかを示すようになりました。
<!-- sources:R107 -->
- **プラグイン作成スキルの挙動を改善**
  - 関連: `plugin-authoring`
  - ターミナルが無いセッションで端末コマンド実行を提案せず、モジュール共有は要求があったときのみ説明します。
<!-- sources:R108 -->
- **Grep入力の `-l`、`-c`、`-r` フラグ対応を追加**
  - 関連: `grep`
  - Grep検索で `-l`、`-c`、`-r` フラグが付与された場合でもエラーせずに検索が実行されます。
<!-- sources:R109 -->
- **claude plugin validate とプラグイン読み込みの改善**
  - フックモジュールがトップレベル変数の再バインドで拒否された場合、エラーに再バインド行、原因、修正方法が表示されるようになりました。
<!-- sources:R110 -->
- **Workflow ツールの scriptPath 拒否メッセージの改善**
  - scriptPath が拒否された際に、script パラメータでインラインスクリプトを渡す方法が提示されます。
<!-- sources:R111 -->
- **大容量ファイル送信失敗時の通知改善**
  - アップロード失敗理由が不明な場合でも、ファイルが縮小される代わりに失敗が報告されます。
